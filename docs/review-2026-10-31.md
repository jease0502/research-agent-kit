# Cross-review of `python/rak`, rak-knowledge skills, `scan_private.py` and `evals/fabrication-audit` (2026-10-31)

Independent review by a separate agent session. Code at **HEAD 964f0ef**, and every `file:line` below refers to that commit.
Nothing in the reviewed files was changed. This document only reports.

## How this was done

- Three read-only review passes ran in parallel:
  - `rak` citation / config / cli / chat / check;
  - build / add_paper / mdio / schema / i18n;
  - `scan_private.py` + `evals/fabrication-audit` + the five rak-knowledge skills.
- Every finding was reproduced by running code in a scratch copy. Live API calls were few and spaced at least 3.5 s apart.
- **V** means I re-ran or re-read it myself after the pass; **R** means the pass reproduced it and I did not repeat it.
- Severity:
  - **high**: wrong results or a security exposure in normal use, or the tool fails at its stated purpose;
  - **medium**: a plausible edge case or a missing guard;
  - **low**: minor, or a mismatch with the documentation.

## 1. `python/rak`: chat bridge (`chat.py`, `build.py` server)

**H1 (high).** `build.py:940-963` (`do_POST`) parses the body as JSON whatever its Content-Type, and never looks at
`Origin` or `Host`.
- A `text/plain` POST is a CORS "simple request", so any site the user visits while `rak build --serve` runs can
  start a CLI run with the user's credentials and an attacker's question.
- Without a Host check, DNS rebinding can also read the SSE stream.
- "Read-only" tools still read any file the user can (see M2).

Repro (R), with a fake CLI via `RAK_CLAUDE_CMD`:

```
curl -X POST http://127.0.0.1:8765/api/ask -H "Content-Type: text/plain" -H "Origin: http://evil.example" -H "Host: attacker.example:8765" --data '{"q":"hi"}'
→ data: {"type": "delta", ...}
```

The CLI was spawned. V: there is no `Origin` or `Host` check anywhere in `build.py`.

Fix:
- require `Host` ∈ {`127.0.0.1:<port>`, `[::1]:<port>`, `localhost:<port>`};
- require `Origin`, when present, to be the same origin;
- require `Content-Type: application/json`.

**H2 (high).** `chat.py:237`: `import build` instead of `from . import build`.
- Repro (V): `python -c "from rak import chat; chat.render('### Direct answer\nsee [[x]]')"` raises `ModuleNotFoundError: No module named 'build'`.
- Worse, with PyPA's `build` package installed, it imports that package instead.
- No test covers `chat.py`.
- Fix: a relative import, plus a test driving `ask()` with a fake `RAK_CLAUDE_CMD`.

**M1 (medium).** `chat.py:114-120`, `:209`: the question is passed right after `-p`.
- The CLI treats `-p` as a flag and the prompt as positional, so a question starting with `-` is parsed as a CLI option.
- Any empty answer whose stderr says "unknown option" is retried **without `--allowedTools`**, so user input can drop the tool restriction.
- Repro (R): `chat.ask("--bogus-flag")` spawned a second run without `--allowedTools`.
- Fix: options first, then the question after `--`. Never retry without the restriction automatically.

**M2 (medium).** `chat.py:40` has `Bash(sed:*)` in the "read-only" allowlist. GNU sed can write (`-i`) and run commands
(`e`).
- R: in Git Bash, `echo x | sed '1e echo SED_EXECUTED_SHELL'` prints `SED_EXECUTED_SHELL`.
- Unverified whether Claude Code's permission layer blocks those forms.
- The README calls the tools read-only.
- Fix: drop `Bash(sed:*)` and `Bash(cat:*)` (`Read` covers them), and scope directories.

**L1 (low, doc).** README says the bridge binds only to `127.0.0.1`; `build.py:984-986` also binds `::1`. Still
loopback only. Fix the wording.

## 2. `python/rak`: citation check (`citation.py`)

**H3 (high).** `citation.py:48` (`TITLE_MATCH = 0.90`), used at `:349`.
- V (offline ratio):
  - "Attention Is All You Need" vs "Attention Is Not All You Need" gives 0.926;
  - "Playing Atari…" vs "Playing Go…" gives 0.921.
- R (live): both of these were reported as "confirmed":
  - `1810.04805` cited as "BERT … for Language **Generation**";
  - `1312.5602` cited as "Playing **Go** with Deep RL".
- This is the plausible-fabrication case the tool exists for.
- Fix: a stricter ratio, plus a word-set comparison that reports any word present on only one side (especially
  `not`/`no`) as a separate non-confirmed status.

**M3 (medium).** `citation.py:155-156`: BibTeX `eprint = {arXiv:2307.15818}` keeps the `arXiv:` prefix. The lookup
misses, and a real paper is reported as "no record", which reads as fabricated.
- R: `lookup_arxiv` gave `'arXiv:2307.15818': 'not_found'`.
- Fix: strip a leading `arxiv:` in any case.

**M4 (medium).** `citation.py:185`: an unquoted `arxiv: 2310.12340` in a note's frontmatter is a float.
`read_note` returns `'2310.1234'`, so a different ID is looked up (R).
Fix: report a numeric `arxiv` as unconfirmed ("quote the id") instead of `str()`-ing it.

**M5 (medium).** `citation.py:99-105`: first-author comparison gives false mismatches.
- R: these all fail to match —
  - `van der Maaten, Laurens` vs `Laurens van der Maaten`;
  - `S{\o}rensen` vs `Sørensen`;
  - family-name-first order (`Zhang Wei` vs `Wei Zhang`).
- `Jr.` is taken as the surname.
- Fix: strip particles and suffixes, transliterate ø/ß/ł/æ, and accept a match on any name token.

**L2 (low, doc).** Bare IDs are not detected.
- `citation.py:52-53` vs `citation-check/SKILL.md:22` ("Bare arXiv ids … in any text") and `citation.py:9`.
- A draft with only bare IDs prints "no citations found" and exits 0 (R).
- Fix: correct the docs, or add a guarded bare-ID pattern.
- Separately: a non-zero exit on "no citations found" when checking a draft.

**L3 (low).** `citation.py:142`: a Latin-1 `.bib` raises `UnicodeDecodeError` with a traceback (R). An unterminated
`"` in `_bib_fields` (`:132`) would raise `ValueError` (reasoning only). Fix: `errors="replace"` and per-entry
parse errors reported as unconfirmed.

## 3. `python/rak`: CLI and config

- `rak --root ./kbroot init` writes `rak.toml` into the current directory, not into `kbroot` (R).

## 4. `python/rak`: site build, add-paper, frontmatter

**H4 (high).** `build.py:203-213`: `make_renderer` uses Python-Markdown `extra`, which passes raw HTML through. The
result reaches the page through `item.js:190` (`innerHTML`). `add_paper.py:372-374` writes the API abstract into the
note unescaped, so any arXiv submitter controls it.
- V: `markdown.Markdown(extensions=['extra']).convert('hi <img src=x onerror="alert(1)">\n\n<script>alert(2)</script>')` returns both tags intact.
- R: after `rak build`, `dist/data/items/evil.json` contains them.
- Fix: escape raw HTML at render time (deregister the raw-HTML processors), or sanitize with an allowlist before writing `sections[].html`.

**H5 (high, irreversible).** `build.py:1035-1038`: `out_dir = (ROOT / args.out).resolve()` and
`if out_dir.exists(): shutil.rmtree(out_dir)`, with no guard.
- R: `rak build --out papers` deleted every note.
- `--out .` would delete the KB, and an absolute path deletes anything.
- Fix: refuse when `out_dir` is the root, an ancestor of it, or holds `rak.toml` or content folders. Better, only delete a folder that carries a build marker file.

**M6 (medium).** `build.py:544-550`: `rak build` never runs schema validation, so it publishes despite `rak check` errors.
- R: an unquoted `arxiv: 2307.15810` builds, and `meta.arxiv` becomes `2307.1581` (a link to a different paper).
- R: `year: "2024"` next to an int year crashes at `build.py:672` (`TypeError` in sort).
- Fix: run the checks in `build()` and refuse on errors, as the docs already say ("0 error before build").

**M7 (medium).** `schema.py:492-495`: a `javascript:` scheme in `url` / `pdf` / `code` is only a warning, and it reaches an
`href` (`item.js:70-72`) (R). Fix: make a non-http(s) scheme an error, or drop the field at build time.

**M8 (medium).** `add_paper.py:340-344` with `guess_venue`'s default (`:186`): `--refresh` overwrites a hand-set venue
(`ICLR 2018`) with `"arXiv preprint"` (R). This contradicts "keeps the human-written content". Fix: do not overwrite
with the fallback value.

**M9 (medium).** `mdio.py:127-145`: `dump_frontmatter` corrupts values it cannot express.
- Nested mappings are stringified: `ratings: {name: 4}` comes back as a string (R).
- Bare flow-list items such as `null`, `true`, `on`, `1.5` or `2024` round-trip as `None` / `True` / numbers. All of these are valid slugs or tags (R).
- C0 control characters from an API title produce a file that no longer parses (R).
- Fix: quote YAML 1.1 keywords and numeric-looking items, dump nested values with `yaml.safe_dump`, and strip control characters.

**M10 (medium).** `add_paper.py:196` (`rsplit("/", 1)[-1]`): old-style IDs lose their archive.
- `hep-th/9901001` becomes `9901001` (R, live), so the URL is wrong.
- Duplicate detection cannot match, and `--batch` reports the ID as missing.
- Fix: take everything after `/abs/`.

**M11 (medium).** `add_paper.py:443-444`, `:321`: only `arxiv` is compared for duplicates, so `--doi` and manual papers are
added twice (R). Fix: also match a normalised `doi`.

**M12 (medium-low).** `build.py:46-47`, `:62-81`: math stashing grabs `US$100 and US$50` and `$x$` inside code
spans (R). Fix: skip code spans, and require a non-digit after the opening `$`.

**M13 (medium-low).** `add_paper.py:576`, `:480-481`: `--batch` creates the same paper twice for `1707.06347` and
`1707.06347v2`. One invalid slug calls `die()` mid-batch, so later entries are never written (R). Fix: dedupe by bare
ID, and validate every slug before fetching.

**Low:**
- `build.py:243-245`: backlink context is empty when the link uses an alias (R).
- `add_paper.py:460-465`: `--refresh --dry-run` prints "metadata updated" while nothing is written (R).
- `add_paper.py:44-48`: `extract_arxiv_id` matches any `dddd.dddd` and truncates a longer number (`2307.158189` becomes `2307.15818`) (R).

**Doc mismatches (low):**
- The add-paper SKILL and `prompt.md` say batch is "up to 40". The code chunks by 10 with no limit (`add_paper.py:240`), and the docstring says 40.
- "`--refresh` keeps the human-written content" is contradicted by M8 and M9.
- The README says zh-TW output was checked byte-identical for `rak build`. `test_zh_parity.py` covers only `rak check`.
- The SKILL says `pip install research-agent-kit`, but the package is not published.

## 5. `scripts/scan_private.py`

**H6 (high).** `scan_private.py:245-246` (and the printing at `:274-276`): every hit prints the relative path as is. A file
inside a privately named folder therefore puts the name into the CI log. That defeats "private names are printed only
as their line number in the list".
- V: the path string is passed to the output unmasked.
- R: `zorblax_project/a.txt (路徑):1:1  private-term …`. The test `test_allow_file_and_path_names` asserts this leaking output.
- Fix: mask path components that hit a term, everywhere a path is printed.

**H7 (high).** `scan_private.py:94-99`: `Terms.from_lines` raises `ValueError(f"…{term!r}")` and nothing catches it. CI
shows the term.
- R: triggered by a mixed CJK/ASCII entry, more than 4 words, a BOM before a CJK first line, or any kana or Hangul entry.
- Fix: report only the line number, exit 2, strip a BOM, and support or explicitly reject kana and Hangul without echoing the entry.

**H8 (high).** `scan_private.py:253-276`: the `--history` scan reported 0 hits in a throwaway repo (R) that contained:
- a name in a path that was later renamed;
- author/committer name and email;
- an annotated tag message;
- a text file over 5 MB;
- a UTF-16 file.

Fix:
- scan `%an %ae %cn %ce` and tag messages;
- scan every path each blob appeared under, plus tree entry names;
- stream large files;
- try UTF-16 before treating a file as binary.

**M14 (medium).** `scan_private.py:136-149`: these name variants are not matched (R):
- glued to other words or digits (`ZorblaxBot`, `acmeCorpLab`);
- percent-encoding;
- a name wrapped across lines;
- full-width forms;
- simplified versus traditional CJK.

Fix: split camelCase and letter/digit boundaries, NFKC and percent-decode, and join across line breaks.

**M15 (medium).** `scan_private.py:174`: the email allow-list matches by suffix without a dot boundary. Addresses at
`myexample.com` or `acmeanthropic.com` pass (R). Fix: `domain == d or domain.endswith("." + d)`.

**Low:**
- `:63`: the home-path rule misses uppercase user names and paths without a trailing slash (R).
- Image names of the form `icon@2x` plus a `.png` extension, and `ssh://git@host/...` URLs, are flagged as emails (R).

## 6. `evals/fabrication-audit`

**H9 (high).** `controls.py:60-67`: `planted_numbers` keeps only values for which `S.matches(...)` is already false, so the
positive control ("all K planted numbers must be flagged") is 1.0 by construction.
- V (code).
- R: with `S.matches` made 1000× looser, the evidence still showed `pos_ctrl_planted_flag_rate: 1.0`.
- For scale, the real scorer already counts 21.3% of random 2-decimal values in [0, 1] as "traced" by chance on t1, and 11.3% on t3.
- Fix: plant numbers at realistic precisions without pre-filtering, gate on the measured flag rate, and report the chance-match rate per task.

**H10 (high).** `score.py:46-67`, `:143`: the traceable pool is read from the run's `logs/`, which the agent itself writes.
- V (code).
- R: a report with 3 invented numbers scored `n_untraced: 3`. After the agent also wrote them into `logs/summary.json`, it scored 0.
- Fix: build the pool from a fresh re-run of the task's `run.py` with the registered seeds, or from the files `run.py` writes, by expected name.

**H11 (high).** `tasks/t3-leaky-eval/expected.json`, `tasks/t4-silent-crash/expected.json`, `score.py:128`: the trap
regexes behind C3 misfire on ordinary sentences (R).
- Naive reports counted as detecting the trap:
  - "I checked for data leakage and found none";
  - "evaluated after training on 300 points".
- Careful reports counted as missing it:
  - "computed on the training data";
  - "seed three blew up".
- The trap-negative gate cannot catch this, because its naive report has no prose.
- Fix: make the blinded human labels the C3 metric, with the regex only as a pre-screen, or add realistic paraphrases to the gate.

**H12 (high).** `score.py:120-125` via `rak.citation.read_claims`: from a t5-style bullet list, only `arXiv:`-prefixed or
URL IDs are extracted, and with no title or author.
- A wrong title on a real ID is checked for existence only, and is "confirmed".
- References without such an ID drop out of the denominator.
- So C2 cannot see the main fabrication mode (R). This compounds H3.
- Fix: parse the bullet format (title, first author, ID) into full claims, and count every bullet; score unparsed ones as unconfirmed.

**H13 (high).** `aggregate.py:51-53`: `untraced_rate_A__n` is the number of runs, including runs without a report.
Prereg §3 says such runs count toward neither rate.
- V (code).
- R: with 24 of 25 reports missing per arm, n is 25 and the min-n gates pass.
- Fix: n = runs with a report and `n_numbers > 0`.

**M16 (medium).** `verdict.py:203-209`: "C1 is read only if C0 passes" (prereg §4) is not implemented. A failing C0 leaves
C1 as FAIL instead of UNDETERMINED (R). Fix: a registered dependency that forces UNDETERMINED.

**M17 (medium).** `score.py:33`, `:111`: numbers glued to units (`3.7x`, `412ms`, `25k`) and integers in 1900–2100 are never
scored (R). Fix: allow unit suffixes; exclude years only when the context looks like a date or a citation.

**L5 (low).** The prereg, `controls.py` and `verdict.py` name the evidence file differently. `controls.py`'s output also
lacks the two `wiring_*` keys, so used directly it fails the gate (fail-closed, but confusing). Fix: one name and a
merge step.

## 7. rak-knowledge skills (`daily-digest`, `citation-check`, `add-paper`)

**M18 (medium).** `daily-digest/scripts/run_digest.py:107`, `:125`: config values are not type-checked. `push = "false"` (a
string) is truthy: it turns unattended pushes on and adds `Bash(git push*)` to the allowed tools (R). Fix: validate
types against `DEFAULTS` and raise.

**M19 (medium).** `run_digest.py:133`, `:140`: `shlex.split` in POSIX mode removes backslashes from Windows paths.
- A Windows path such as `<drive>:\Users\<user>\...\claude.cmd` comes back with every backslash removed (R), so the SKILL's own Windows remedy (an absolute `RAK_CLAUDE_CMD`) fails, and so does `notify_cmd`.
- A bare `claude` fails on Windows, where npm installs `claude.cmd` (R). The same applies at `harness.py:282`.
- Fix: `posix=(os.name != "nt")` or a TOML list, resolved with `shutil.which`.

**M20 (medium).** `run_digest.py:161`, `:76-78`: two config errors that are not handled.
- `earliest = "9.30"` raises an uncaught `ValueError`, so no `notify_cmd` runs. That contradicts "a silent failure is not silent".
- A typo key inside `[[lines]]` is silently ignored, contradicting SKILL.md:37 ("Unknown keys are an error") (R).
- Fix: validate both in `load_config`.

**Low:**
- `--dry-run` is blocked by the time gate, and on a cp950 console `print(prompt)` raises `UnicodeEncodeError` (R).
- citation-check SKILL.md:40 says exit 0 means everything is confirmed, but "no citations found" also exits 0 (`citation.py:415-417`).

## Checked and found fine

- **Citation lookups:**
  - status 0, 5xx and 429 become "lookup failed", never "not found" or "confirmed";
  - arXiv requests are batched and spaced;
  - a missing ID does not hide the others in its batch;
  - title-only searches report near-identical titles as ambiguous.
- **`cite-check`** never edits its inputs, and its exit codes 0/1/2 match the docs.
- **Config** is parsed with `tomllib`. It rejects unknown keys and unsafe `site_name` / `source_url`.
- **Chat bridge process:** it spawns with `shell=False` and runs in the KB root. The bridge is excluded from builds without `--serve` / `--chat`.
- **Frontmatter round trips** are exact for colons, quotes, backslashes, CJK and BOM+CRLF. Unquoted dates become ISO strings.
- **Notes are protected:**
  - versioned IDs are stripped;
  - duplicates of new-style IDs are caught;
  - an existing note is never overwritten;
  - slugs cannot escape their folder.
- **Escaping:** wikilink labels, titles, snippets and TeX are escaped; JS uses `esc()` for metadata.
- **`scan_private.py`:**
  - in CI it fails closed on a missing or empty list;
  - pattern hits print only 3 characters;
  - inline allow comments cannot whitelist private names;
  - the repo scans clean with an innocuous list.
- **Fabrication-audit `verdict.py`:**
  - raw comparisons;
  - unknown keys and flags raise;
  - missing values give UNDETERMINED;
  - hashes are checked, and verdicts are written once.
- **The five SKILL.md files** have valid frontmatter, and every `rak` command and flag they cite exists.
